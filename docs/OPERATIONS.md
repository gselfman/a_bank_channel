# Управление

Все команды ниже из корня проекта. `bash deploy/channel` вызывает CLI в контейнере. Единственная база state/channel.sqlite3 привязана к одному каналу, удалять её нельзя. Worker берёт межпроцессную блокировку только на цикл; если CLI встретил работающий цикл, повторите позже.

## Начальный комплект

`seed` импортирует одобренные пользователем 35 постов ровно один раз. Повторный импорт не меняет состояния отправленных сообщений. Порядок: темы 1–27, 29–34, 28, 35. Навигация — текстовое сообщение, остальные — фото с HTML-подписью. Для каждой успешной отправки сохраняется message_id. Оригинальный просмотр — content/review.html.

## Новые материалы

```bash
bash deploy/channel poll
bash deploy/channel status
bash deploy/channel generate tg-1560
bash deploy/channel image ai-tg-1560
bash deploy/channel review
# Откройте state/review.html локально (scp). Не публикуйте его на открытом сервере.
bash deploy/channel approve ai-tg-1560
bash deploy/channel schedule ai-tg-1560 --at 2026-10-28T10:00:00+03:00
bash deploy/channel resume
```

ID здесь — пример; используйте реальные из status. Для `generate` требуется успешный свежий poll обоих сайтов, ключ API и положительные лимиты бюджета. `image` создаёт платное изображение, поверх которого код помещает точный оригинальный логотип. Повтор image до approve заменяет картинку, поэтому проверяйте её ПОСЛЕ последней генерации. `approve` — явное подтверждение человеком текста, доказательств и изображения. Устаревшие/изменившиеся доказательства блокируют approval или отправку.

`config.json`: ai_enabled включает генерацию текстов на каждом poll; ai_images_enabled добавляет картинки для новых draft. В обоих случаях публикация остаётся на ручном approve. schedule_enabled назначает будущие часы из publish_times_moscow только approved AI-постам. По умолчанию всё это выключено, бюджет 0. После изменения config перезапустите контейнер (конфигурация читается при старте). Поздно запущенный worker не пытается массово догнать пропущенные слоты. Первый poll Telegram устанавливает baseline; последующие идут назад по страницам до сохранённого номера, чтобы не потерять промежуточные новые сообщения.

При review проверить смысловое соответствие ВСЕХ утверждений источникам: проверка точной цитаты программой не доказывает вывод ИИ. Отдельно проверить тарифы АБанка, регион/сеть/ограничения, отсутствие чужих ссылок. Изображения будущих постов не содержат цены, текст и логотип из генерации: логотип накладывается точно.

## Расходы OpenAI

Настройте ai_budget.monthly_usd, text_reservation_usd, image_reservation_usd и суточные количества вызовов. Значения reservation задаются с запасом по актуальной цене выбранных моделей и ограничению контекста/выхода. Они не являются автоматически рассчитанной ценой API. До запроса резерв списывается атомарно, даже если запрос завершился ошибкой или неизвестным исходом; автоматических оплаченных повторов нет. usage сохраняется в БД. Установите отдельные доступные ограничения/оповещения проекта OpenAI; локальная оценка не гарантирует долларовый предел фактического счёта. Часовой пояс счётчика месяца/суточных вызовов — UTC, публикаций — Москва.

## Ошибки Telegram

При HTTP 429 scheduled-пост остаётся scheduled, due переносится по retry_after. Первичный пакет останавливается, остаётся paused до повторного запуска. HTTP 4xx даёт failed. Таймаут, разрыв сети, HTTP 5xx или смерть процесса оставляют uncertain/sending: неизвестно, принял ли Telegram сообщение. Последующие отправки блокируются. Telegram не предоставляет ключ идемпотентности для sendPhoto; гарантировать exactly-once невозможно.

Осмотрите канал вручную. Если сообщение есть, скопируйте его реальный message_id из ссылки:

```bash
bash deploy/channel reconcile seed-7 --message-id 123
bash deploy/channel resume
bash deploy/channel publish-initial --live
```

Если точно НЕ отправлено:

```bash
bash deploy/channel reconcile seed-7 --not-sent
bash deploy/channel resume
bash deploy/channel publish-initial --live
```

Не выполняйте --not-sent наугад. Для AI-поста аналогично с его ID. failed с ошибкой параметров сначала исправить, затем reconcile. Редактирование/пин можно повторить через finalize; unpin чужих сообщений и удаления сообщений нет.

## Остановка, резервирование, восстановление

`pause` блокирует отправку, но не чтение источников. `docker compose stop` останавливает также сбор/ИИ. `backup` создаёт согласованную SQLite-копию через backup API. Копируйте также state/images и state/drafts, исходный git commit, конфигурацию. Секреты резервируйте отдельно с доступом только владельцу. Для cron: `cd /path/to/repo && bash deploy/channel backup` (если занят цикл — повторить позже). Контролируйте ротацию локальных резервных копий.

Восстановление: остановить worker, сохранить текущую БД отдельно, вернуть проверенную копию на channel.sqlite3, убрать только устаревшие -wal/-shm при ОСТАНОВЛЕННОМ процессе, восстановить images/drafts и права UID 10001, проверить status и последние message_id по каналу. Восстановление старого бэкапа может потерять сведения о последних отправках: обязательно reconciliation до resume. Один экземпляр worker на одну БД/канал; нельзя запускать независимую копию с пустой БД в тот же канал.
