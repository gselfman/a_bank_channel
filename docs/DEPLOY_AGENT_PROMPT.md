# Задание агенту: установить и запустить A-Bank Channel

Работай в `gselfman/a_bank_channel` на сервере Ubuntu 20.04. Владелец разрешил установить сервис и опубликовать согласованные 35 материалов в @a_bank_wallet. Повторно согласовывать эти тексты не нужно. Серверные секреты вводит владелец в локальном терминале через `python3 deploy/configure_secrets.py`; не проси его вставлять секреты в чат. Ничего не печатай из `.env`, не включай его в коммиты, отчёт, команды с аргументами или логи. Не меняй действующие сайты и чужие сервисы.

Сначала прочитай README.md, docs/DEPLOY_UBUNTU.md, docs/OPERATIONS.md, docs/EDITORIAL_RULES.md, docs/KNOWN_LIMITATIONS.md. Проверь текущую ветку, наличие всех 35 картинок/текстов и состояние сервера. Все команды запускай из корня проекта. Не удаляй существующий каталог state и не пересоздавай базу при обновлении: это приведёт к повторным публикациям.

1. Проверь свободное место, Docker/Compose и доступ к api.telegram.org, t.me, altyn.one, a-bank.ru, api.openai.com. Из этой среды никакие реальные публикации и оплаченные API-запросы ещё не проверялись. Выполни unit tests. На Ubuntu 20.04 используй контейнер Python 3.12; не заменяй системный Python. Если Docker отсутствует — установи из доступных пакетов по инструкции. Не удаляй чужие контейнеры и образы.
2. Клонируй приватный репозиторий через существующий доступ GitHub или read-only deploy key. Не запрашивай PAT в чате. Создай state с владельцем UID/GID 10001. Построй контейнер. Попроси владельца выполнить локальный скрытый ввод секретов, если `.env` ещё нет. Проверяй наличие полей, не их значения.
3. Выполни `seed`, `preflight`, `status`. Preflight должен показать ожидаемый канал и имя бота и подтвердить право публикации/редактирования (пин в канале входит в редактирование). Если бот или канал неожиданны — останови отправку, сообщи конкретное расхождение. Канал может содержать другие сообщения: их не удалять.
4. Открой content/review.html. Все 35 текстов и картинок уже одобрены владельцем. Сохрани ссылки с SAhtmEI, видимый @abank_wallet_bot и https://wallet.a-bank.ru, поддержку @a_bank_support_bot. Никаких оригинальных ссылок Алтына/Дзена в клиентские посты не добавлять. Тема 28 (навигация) идёт предпоследней и публикуется текстовым сообщением: все ссылки на 33 темы могут не поместиться в подпись к фото. Для неё обложка хранится, но не отправляется. Тема 35 последняя.
5. Непосредственно перед отправкой проверь актуальность временного ограничения СБП, альтернативных способов и сетей из темы 35. Утверждение датировано 26.10.2026. Не выдавай отсутствие предупреждения на сайте за восстановление функции. Если условия поменялись, доложи владельцу конкретную правку; не публикуй заведомо устаревший статус. После фактической проверки выполни `confirm-status`. Не выполняй эту команду просто чтобы обойти блокировку. Не пытайся пройти AML/пополнение реальными деньгами.
6. При корректном preflight и актуальном статусе: `resume`, `publish-initial --live`. Публикуй в исходном порядке с паузой 5 секунд. Рабочий процесс держит блокировку; не запускай параллельный initial publisher. После завершения `status` должен показать 35 sent, `finalize` — собрать ссылки и закрепить навигацию и статус. Если отправка имеет sending/uncertain/failed, сначала осмотри канал и сделай reconcile по инструкции; нельзя просто удалять state, снимать статус или повторять запрос.
7. Выполни `poll`: убедись, что публичная лента t.me/s/altynwallet возвращает сообщения без авторизации, обе группы сайтов содержат читаемый текст. Первый poll устанавливает baseline, не переписывает весь архив. Если сайт/Telegram не открывается или поменял разметку, исправь парсер с фикстурой и тестом; не объявляй мониторинг работающим до реальной проверки. Дополнительный MCP/Telegram-account login для публичной ленты не нужен.
8. Для ИИ запроси только недостающие настройки: месячный лимит USD и частоту публикаций. На данный момент владелец их не задавал. При отсутствии ответа оставь paid AI и schedule выключенными, но мониторинг можно запустить. Проверь доступность выбранных моделей и текущие цены по официальной документации OpenAI. Не подбирай дорогую модель молча. Reservations в config — консервативные оценки на запрос, НЕ точный биллинг; лимиты проекта OpenAI настроить отдельно. Один реальный платный тест только в пределах назначенного владельцем бюджета.
9. Включи ai_enabled и при необходимости ai_images_enabled после конфигурации ключа/бюджета. Новые посты должны оставаться draft/hold до ручного review и approve. Автоматическое расписание назначает время только approved-постам, не черновикам. Настрой будущие часы по Москве только после выбора владельца. Не расширяй согласие на 35 текстов до согласия на любые будущие тексты ИИ.
10. Запусти `docker compose up -d` (или docker-compose -f compose.yaml), проверь heartbeat и события. Настрой резервное копирование БД через штатный backup, а также state/images, state/drafts, `.env` отдельно с закрытым доступом. При перезагрузке Docker должен восстановить worker. Проверь pause/resume. Не открывай публичный административный порт: управление через SSH/CLI.

Итоговый отчёт: commit SHA, версия сервера/контейнера, имя бота и канал, результат реальных проверок, сколько реально опубликовано, ссылки на навигацию/последний статус, включены ли AI/расписание и с какими лимитами, местонахождение резервной копии. Отличай проверенное от оставшегося ненастроенным. Не говори «всё работает», если live-проверка не выполнена.
