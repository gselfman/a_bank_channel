# Правила канала АБанка

Канал — короткий актуальный справочник возможностей кошелька, а не копия истории Алтына. Базовые функции подтверждать на https://altyn.one/ и продуктовых страницах/FAQ. Цены, комиссии, лимиты и юридические данные — только АБанк, https://a-bank.ru/. Отсутствие подтверждения не трактовать как согласие. При расхождении — hold и проверка человеком.

Уже согласовано 35 исходных постов с обложками. Исторические условия от владельца на 26.10.2026: брокер 2%; партнёрская программа 50% доходов АБанка от учитываемых операций приглашённых; цена выпуска Visa не указывается на изображениях. Комиссия за покупки 0% не означает отсутствие комиссии за обмен/переводы. Не обещать гарантированное прохождение AML, одобрение платежа или «чистая крипта всегда зачислится».

Исключаем видео, служебные записи, старые техработы/аварии, конференции, корпоративные новости, продажу франшиз, прошедшие праздники и акции. Новые своевременные календарные темы можно готовить после проверки даты. Новые ограничения функциональности направлять человеку срочно; не скрывать их как «ненужные технические новости». Анонсы действующих функций превращать в инструкции в настоящем времени. Полезную суть текстов сохранять, отсутствующие подробности не придумывать. Ссылки на Дзен не публиковать.

Ссылки: видимый @abank_wallet_bot ведёт на https://telegram.me/Abank_wallet_bot?start=SAhtmEI; видимый https://wallet.a-bank.ru ведёт на https://wallet.a-bank.ru/?a_bank=SAhtmEI. Поддержка только @a_bank_support_bot. Партнёрские параметры обязательно сохранять.

Тема 35 — последний пост о способах пополнения с предупреждением про СБП. При первичной публикации проверить актуальность указанного статуса; дата в историческом тексте не обновляется автоматически без проверки. Навигация публикуется предпоследней, после этого обновляется ссылкой на статус. Оба сообщения закрепляются без удаления других закреплений.

ИИ получает только ограниченный контекст источников, не секреты и не права отправки. Выдаёт структурированный черновик и точные цитаты; программа проверяет наличие цитат. Человек проверяет, доказывают ли они каждое утверждение, затем approves. Никогда не включать автоматическое утверждение просто потому, что API выдал decision=draft.

## White-label наследование функциональности (уточнение владельца 28.10.2026)

A-Bank — white-label кошелька Altyn на той же платёжной инфраструктуре. Официально подтверждённые в источнике Altyn изменения статуса и функциональности платёжных операций наследуются A-Bank автоматически, если нет конкретного противоречащего свидетельства: СБП, методы оплаты и пополнения, сети криптовалют, ввод/вывод, переводы, доступность сервисов кошелька, исправления сбоев. Отдельное подтверждение на сайте A-Bank для **каждого** такого изменения не требуется. Не пропускать существенные сообщения Altyn о восстановлении сервисов.

Исключения: **тарифы, комиссии, стоимость выпуска карт, партнёрские выплаты, брендовые акции, юридические условия и специальные предложения** могут различаться между Altyn и A-Bank. Их нельзя переносить без проверки условий конкретно A-Bank. Известное историческое отличие: брокерская комиссия Altyn 1,5%, A-Bank 2%; считать только историческим ориентиром, текущий тариф перепроверять. Противоречие в данных — отложить публикацию с объяснением.

Темы, проходящие продуктовый фильтр: фактические обновления операций и клиентских возможностей. Исключить конференции, саммиты, локальные встречи, события без продуктового эффекта, общие отраслевые новости, продажу франшизы. Всякое утверждение должно вытекать из источника; рекламные преувеличения запрещены. Перед добавлением в GitHub проверять отсутствие дублей по теме и первоисточнику, подбирать соответствующую правомерную иллюстрацию; без подходящей картинки не создавать публикацию.

## Ссылки на Altyn в клиентских постах (29.10.2026)

Используй Altyn как внутренний первоисточник для проверки фактов и сохраняй ссылку в служебном поле JSON `source`, но **никогда не вставляй URL altyn.one, t.me/altynwallet или другие брендовые ссылки Altyn в публичное поле `text`**. Не направляй клиентов A-Bank на инструкции, кошелёк, поддержку или акции Altyn. В публичном тексте допускаются ссылки только на A-Bank и нейтральные внешние сервисы, когда они нужны. Если инструкция есть только у Altyn, передай её смысл своими словами без ссылки на Altyn; не добавляй не подтверждённых деталей. Перед записью файла проверь отсутствие Altyn URL в поле `text` (регистронезависимо), а источник оставь в поле `source` для аудита.

## Устойчивое чтение Telegram и обязательный учёт пропусков (06.11.2026)

**Запрещено объявлять «новостей нет», если существуют обнаруженные, но непрочитанные сообщения.** Это состояние `incomplete`, а не `no_news`.

При каждом редакционном цикле:
1. Найти новые ID/даты в `https://t.me/s/altynwallet` и `https://t.me/altynwallet/<id>`. Не ограничиваться только последним ID: смотреть диапазон новых ID и перечень из `editorial/unread/`.
2. Если официальная HTML-страница недоступна или возвращает только обложку, искать **точный** текст через альтернативные источники: `https://telemetr.me/content/altynwallet`, публичную поисковую индексацию, цитаты в репостах. Предпочитать оригинальный текст; вторичные зеркала использовать как вспомогательное подтверждение. Проверить, что материал действительно относится к **@altynwallet**, совпадает по ID/времени/содержанию, не является другим каналом. Не считывать соседний пост как недоступный ID.
3. Если текст либо медиа недоступны или соответствие ID неоднозначно — не выдумывать новость и **зафиксировать нерешённую запись** `editorial/unread/<id>.json` (отдельный файл на ID) с полями `id`, `source_url`, `first_seen_on`, `last_checked_on`, `status: unread`, `reason`, `attempted_sources`. При уже существующем файле — обновить его через GitHub update_file, не создавать вторую запись. Отсутствие записи в GitHub при ошибке инструмента явно указывать в отчёте.
4. Каждый следующий цикл повторно проверяет все `unread` ID, даже если появились более новые сообщения. После достоверного чтения — изменить тот же файл на `status: reviewed`, `reviewed_on`, `decision: published|duplicate|filtered|insufficient_evidence`, указать фактическую ссылку и краткую причину решения.
5. Только после сравнения с 35 исходными постами, очередью `posts/pending/` и опубликованными материалами принимать решение о новой публикации. Операционные изменения Altyn применяются к white-label A-Bank; условия бренда — не автоматически. Изображение проверять; публичное поле `text` не должно содержать брендовых ссылок Altyn, `source` хранит первоисточник.
6. Итоговый отчёт должен явно содержать: `new_posts`, `unread_count`, список непрочитанных ID, `status=complete|incomplete`. При `unread_count>0` категорически не писать, что все источники проверены или что новых новостей нет; корректная формулировка — «подтверждённых новых публикаций нет, остаются непрочитанные сообщения».
7. Не создавать повторных напоминаний/постов для недостоверного текста. Никаких OpenAI API и прямой отправки в Telegram.

Системная граница: резервные публичные индексы могут отставать и не всегда дают исходный ID. Такое несовпадение не подтверждает сообщение, а оставляет его `unread`.

## Два редакционных потока: новости и полезные инструкции (07.11.2026)

Владелец разрешил **автоматически** публиковать не только подтверждённые продуктовые изменения, но и новые полезные инструкции по уже существующим функциям A-Bank. Это не отменяет фильтры фактов, бренда и дублей.

**Поток 1 — оперативные новости (приоритет):** запуск/отключение/восстановление СБП, карт, платежей, пополнений, выводов, переводов, новых платёжных методов, критические ограничения. Официальные сообщения Altyn об общей платёжной инфраструктуре применяются и к A-Bank, если нет исключения. Не откладывать такую новость ради календарного обучающего материала. Не переносить автоматически брендовые цены, комиссии, юридические условия и акции.

**Поток 2 — практические инструкции (при отсутствии новых новостей):** пошаговые способы использования **подтверждённо доступных** функций A-Bank; типовые ошибки и безопасные действия; карты и зарубежные покупки; пополнение и вывод; выбор сетей; безопасность кошелька. Использовать актуальные первоисточники, проверять ограничения и не обещать, что сторонний платёж точно пройдёт. Инструкция должна приносить самостоятельную пользу без перехода на Altyn. Не переписывать ранее опубликованные 35 постов другими словами: новая инструкция должна иметь новый сценарий, существенное новое пояснение или актуализацию реально изменившихся условий. Рекламные статьи, отраслевые новости и локальные события остаются запрещены.

**Политика частоты:** редакция по-прежнему запускается 09:00/14:00/19:00 Europe/Moscow. Приоритет — оперативная новость. Когда новых новостей нет, проверять возможность одной содержательной инструкции за день (не обязательная квота; отсутствие свежей полезной темы — нормальный исход). Максимум 1 готовый материал в одно серверное окно и не более 3 за цикл. Сверять ранее опубликованные материалы, pending и источники; не добавлять инструкцию, если уже есть готовый близкий пост, даже если нет уверенного статуса отправки. Если окно уже занято — планировать следующее свободное.

**Неизвестные Telegram ID:** продолжаем повторно разбирать editorial/unread, явно отмечаем status=incomplete, если есть unread. Наличие unread не блокирует *другие независимо проверенные* практические инструкции или новости, но никакого вывода о содержимом unread делать нельзя.

**Технические условия публикации:** JSON в posts/pending/ с id,title,text,source,publish_at,image,status=ready, только после проверки содержимого, отсутствия дублей и наличия правомерной релевантной иллюстрации. Никогда не размещать брендовые URL Altyn в публичном поле text; ссылка на первоисточник допускается только в служебном source. Источник/историю происхождения не выдумывать. Без картинки и без доказанной пользы — не создавать ready. Не отправлять напрямую в Telegram. Публикатор Ubuntu не использует OpenAI API.

**Итог каждого цикла:** отдельные счётчики news_posts, guide_posts, unread_count; список публикаций GitHub, а также причину отсутствия новых материалов, если обе категории пусты.
